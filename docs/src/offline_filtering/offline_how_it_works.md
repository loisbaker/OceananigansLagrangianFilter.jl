# How it works
The offline Lagrangian filter uses many of the same helper functions as the online filter, but since the calculation doesn't need to be integrated into the user simulation, the steps are hidden and performed within the function [`run_offline_Lagrangian_filter`](@ref). These steps can be seen in the [`source code`](https://github.com/loisbaker/OceananigansLagrangianFilter.jl/blob/main/src/OfflineLagrangianFilter/run_offline_lagrangian_filter.jl), where steps 1-3 are in `run_forward_and_backward_passes`. In outline:

1. **Set up the model.** The original variables (auxiliary fields), filtered variables (tracers) and their forcing are created with [`create_original_vars`](@ref), [`create_filtered_vars`](@ref) and [`create_forcing`](@ref), and used to build a `LagrangianFilter` model.
2. **Forward pass.** A [`BufferedDataReader`](@ref) is created with [`create_buffered_reader`](@ref) (`direction = :forward`). It holds two saved frames at a time, read directly from the original file, and interpolates linearly in time between them. The filtered variables are initialised from the data with [`initialise_filtered_vars_from_data`](@ref), and the callback [`update_input_data!`](@ref) updates the model's velocities and original variables from the reader at every time step (and substep).
3. **Backward pass.** The simulation is run again, starting from the state at the end of the forward pass, with a second reader created with `direction = :backward`. This reads the data backwards in time and reverses the sign of the velocities.
4. **Post-processing.** The forward and backward contributions are summed with [`sum_forward_backward_contributions!`](@ref), and the result can optionally be regridded to the mean position ([`regrid_to_mean_position!`](@ref)), compared with an Eulerian filter ([`compute_Eulerian_filter!`](@ref)) and converted to NetCDF ([`jld2_to_netcdf`](@ref)).

Alternatively, the computation can be customised by calling these helper functions directly rather than running [`run_offline_Lagrangian_filter`](@ref).

A filter with many terms (e.g. a spectrum filter with many frequencies) can be run in batches of terms with the `batch_size` keyword argument of [`run_offline_Lagrangian_filter`](@ref). Steps 1-3 are then run for each batch in turn with a smaller model, and the outputs of the batches are merged before the post-processing, giving the same output as running all the terms together. Batches of the same size are only compiled once, and the compilation time grows faster than the number of terms, so this can be much quicker to compile. A smaller model also needs less memory.
